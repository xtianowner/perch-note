## 1. 一句话定位

> 永远置顶的桌面浮窗记录簿，输入即留时间戳，每条都能一键复制纯文本。

## 2. 用户场景

用户在做主任务（与 Claude 对话 / 看 Chrome / 写代码），需要随时记一笔：
- 一个临时想法
- 一个 URL / 一段命令 / 一个 ID
- 当前任务的进度坐标
- 与外部沟通时摘录的一句话

**关键摩擦点**：传统笔记 app 切窗口就丢焦点；便利贴 app 多数样式重、没时间戳、没法搜。Perch 的核心是**永不消失 + 时间戳 + 易复制**三件套。

## 3. 核心产品决策（已与用户确认）

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据形态 | **混合：默认 timeline 追加 + 任意条可编辑** | 兼顾"流水账无负担"和"事后修正" |
| 内容格式 | **纯文本 (plain text)** | 避免用户输入 markdown 符号时被渲染破坏；复制粘贴到其他工具不带格式污染 |
| 复制行为 | **每条独立 copy 按钮**，复制原始纯文本 | 用户高频场景是把记录贴到对话/邮件/代码注释，不能带 `*` `#` `` ` `` 等字符干扰 |
| 时间戳 | 持久化 `created_at` + `updated_at`；UI 显示 **`updated_at`**（最后编辑时刻）的相对时间，hover tooltip 显示绝对时间；`created_at` 仅用于列表排序 | 用户主要关心"我最后碰这条是何时"；createdAt 留给未来导出 / 排序用 |
| 存储位置 | 本地 SQLite | 离线优先；后期再考虑可选 sync |
| 平台 | macOS + Windows | 跨设备一致 |

## 5. 数据模型

表 `entries` 由三次 migration 组成（见 `src-tauri/src/lib.rs`，sqlx 字节哈希比对，**已上线 SQL 字符串不允许 reformat**）：

**migration v1 — `create_entries_table`**
```sql
CREATE TABLE IF NOT EXISTS entries (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    content     TEXT NOT NULL,            -- 纯文本，原样存储
    created_at  INTEGER NOT NULL,         -- Unix ms
    updated_at  INTEGER NOT NULL,         -- Unix ms (=created_at if never edited)
    pinned      INTEGER NOT NULL DEFAULT 0, -- 0/1 置顶；v1 起即有列，pin UI 已上线
    deleted_at  INTEGER                   -- 软删除时间，NULL=未删
);
CREATE INDEX IF NOT EXISTS idx_entries_created ON entries(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_entries_active  ON entries(deleted_at);
```

**migration v2 — `add_title_column`**
```sql
ALTER TABLE entries ADD COLUMN title TEXT NOT NULL DEFAULT '';
```

**migration v3 — `add_sort_order_column`**（手动拖动排序，追加式 ADD COLUMN，旧行默认 0 → 回落到 `created_at DESC`，零数据丢失）
```sql
ALTER TABLE entries ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0;
```

**约定**：
- `content` / `title` 全程当 raw text 处理，渲染时一律用 `white-space: pre-wrap` 的 `<textarea>` / `<input>`，**不经过任何 markdown / HTML 解析**
- `listEntries()` 的查询 `WHERE deleted_at IS NULL ORDER BY pinned DESC, sort_order ASC, created_at DESC`：置顶组浮顶、组内按手动顺序、未拖动则回落创建时间倒序；前端 `db.sortEntries()` 用同一套键支持乐观更新
- `idx_entries_active` **没有** `WHERE deleted_at IS NULL` 部分索引谓词（完整索引；与最早设计稿不同，迁移已上线不再回改，未来表大可走 migration v3 加 partial index）
- 软删除：`deleteEntry(id)` 写 `deleted_at = now`，无硬删；当前无回收站 UI，长期会累积，留作 V2 处理
- `updateEntry` 的 UPDATE 同样带 `AND deleted_at IS NULL` 防御谓词，避免 EntryItem unmount cleanup 在 entry 已被软删后误"复活"那一行（与 `deletedRef` 短路构成 A+B 双兜底）

## 6. UI 形态（V1 草图）

```
┌──────────────────────────────────┐
│  3 entries              ⚙       │  ← topbar：左 entry 数 / 右 settings 齿轮
├──────────────────────────────────┤
│ 3 min ago        [Delete][Copy] │  ← 每条 header：相对时间 + actions（始终可见）
│ ┌─Title (optional)────────────┐ │
│ │ 找 demo 视频用的关键词       │ │  ← title 单行 input
│ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐ │
│ │ "japanese commute            │ │  ← content live textarea
│ │  documentary"                │ │
│ └─────────────────────────────┘ │
├──────────────────────────────────┤
│ 12 min ago       [Delete][Copy] │
│ https://example.com/foo/bar      │
├──────────────────────────────────┤
│ ┌──────────────────────────────┐ │
│ │ Type, Enter to save…         │ │  ← InputBar：底部固定，autoFocus
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

**交互细节（与代码一致）**：
- 进入 app → InputBar 自动获焦（`InputBar.tsx autoFocus`）
- InputBar 内 `Enter` 提交、`Shift+Enter` 换行；IME composing 期间 Enter 不提交
- 列表排序 **最新在顶**（`ORDER BY created_at DESC`），新条目插入数组头部
- **没有"双击编辑"模式**：每条 entry 永远是 live `<textarea>` + 可选 `<input>` title，输入即改
- **自动保存三重防线**：
  1. **15 s debounce**（`AUTOSAVE_DELAY_MS = 15_000`，最后一次 keystroke 起算）
  2. **blur 立即 flush**（focus 离开 textarea / title）
  3. **unmount cleanup flush**（组件卸载兜底）
  - 保存成功后 header 闪现 "✓ saved" / "✓ 已保存" 1.5 s（`entry.saved` key）
  - draft 与持久化值**完全相等（不 trim）**时不发 SQL —— 保留用户输入的末尾空白等原始字符
  - flush 三道护栏：`inflightRef` 串行化并发写、`persistedContentRef/persistedTitleRef` 作"上次成功写入"基准（避免 prop merge 后误判）、`deletedRef` 短路已删 entry 的 unmount cleanup
- **删除**：`DeleteButton` 始终可见，两步确认 — 首次点变红 "Confirm / 再点确认"，4 s（`CONFIRM_WINDOW_MS = 4000`）内再点真删，否则自动恢复
- **复制**：`CopyButton` 始终可见，点击 → `navigator.clipboard.writeText(buildText())`；**`buildText` 是闭包**，每次点击重读屏幕上的 live draft（含未保存 15 s 内的改动），按钮短暂切到 ✓ 1.2 s
- **复制内容拼装**（`buildClipboardText`）：可选 `title` → `timestamp(updatedAt)` → `content`，三行紧贴；若 Settings 有自定义文本，按 `before / after` 与上面块整体之间空一行
- topbar 实时显示 entry 数（`N entries` / `共 N 条`）
- **异常态**：DB load 失败时整个 list 区显示 `app.dbError` 提示，不闪退
- 窗口拖边可调；`minWidth: 280 / minHeight: 200`（`tauri.conf.json`）

## 7. 跨平台「永远置顶」实现

| 平台 | 实现 | 已知边界 |
|---|---|---|
| macOS | `window.setAlwaysOnTop(true)` + `NSWindow.level = .floating` | 默认 floating level 在 fullscreen app 之上仍可见；进入 "Mission Control" 时短暂被遮 |
| Windows | `SetWindowPos(HWND_TOPMOST)` | 全屏游戏 / 全屏视频可能强制覆盖 — 可接受 |

Tauri 的 `alwaysOnTop` 配置 + `set_always_on_top` API 已封装上述差异，V1 不需要手写 native 代码。
